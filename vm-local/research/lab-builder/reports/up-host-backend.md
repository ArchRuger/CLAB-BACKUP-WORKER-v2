VERSION CAVEAT. Source tree is clab-ui 0.4.0; npm has exactly one version, 0.3.2. HEAD-only: App `slots`, `lifecycleActionsAvailable`, `documentKey`/`invalidateCache` (NPM/dist/App.d.ts vs CA/packages/clab-ui/src/AppContent.tsx:301-317).

1. LAYERING. Browser (standalone-runtime shell + clab-ui) -> same-origin Fastify BFF (CA/packages/app-server/package.json:5) -> clab-api-server (Go, root). The BFF keeps a `clab_session` cookie and holds upstream JWTs server-side (src/auth.ts:158-187, middleware.ts:21-29), translates routes to /api/v1/*, turns NDJSON into SSE, tunnels WebSockets, and (non-obvious) runs the editing engine `TopologySessionCore` in Node over a FileSystemAdapter mapped to API-server file REST (topologySessionManager.ts:187-216). No dockerode, no Docker socket in web/BFF: only apps/vscode-containerlab imports dockerode (CA/pnpm-lock.yaml:453,489); the web image runs `USER node` with no mounts (CA/Dockerfile:34-52). Socket, --privileged and /etc/shadow belong to clab-api-server (API/README.md:151-165). The BFF has no pluggable backend: ClabApiClient is its only upstream (app.ts:28,299; options :37-46).

2. CONTRACT. app-contract is a private package of DTOs only (src/runtime.ts:3). The real contract is ~90 Fastify routes: auth `/api/config`, `/auth/*` (auth.ts:224-421); inspect `/api/runtime/inspect/all|lab`, `/api/lab/status`; topology `/api/topology/sessions|snapshot|command|events` (topologyProxy.ts:517-612); files `/files`, `/api/runtime/file-explorer/*`, `topology-file/create|delete|import-from-url`; lifecycle `/api/lab/{deploy,destroy,redeploy,apply,start,stop,restart}[/stream]` NDJSON (labProxy.ts:385-720); images; terminals (+WS); wireshark (edgeshark, packetflix, VNC +WS); netem; SSE `/api/events`; UI custom-nodes/icons (runtimeProxy.ts). Inside clab-ui the stable contract is protocol v1: get-snapshot/command -> snapshot/ack/reject/error, 20 commands (core/types/messages.ts:37-101).

3. MINIMUM SUBSET. (a) Pattern B `createApiClabUiHost`: four routes (CA/packages/clab-ui/INTEGRATORS.md:390-500). But `/command` means all 20 commands with comment-preserving YAML, annotations, undo/redo; upstream that is TypeScript TopologyHostCore, ~7.9k lines (core/host 1489, io 2841, parsing 3558), not the Go server. A FastAPI version is a rewrite. (b) Pattern C, smallest backend: run `TopologySessionCore` in the browser with our own `FileSystemAdapter` (readFile/writeFile/unlink/rename/exists + string path helpers; core/io/types.ts:42-88). Both are public exports in 0.3.2 (NPM/dist/session/index.d.ts), the core has no node: imports, and upstream's Pages sandbox does exactly this (standalone-runtime/src/pagesSandboxRuntime.ts:891-902,914-961). FastAPI then serves only a two-document file API: `<lab>.clab.yml` + `<lab>.clab.yml.annotations.json` (naming the manager already uses, MGR/clab-backup-ui/app/host_files.py:143). Saves are tmp-write, backup-rename, rename, unlink (TransactionalFileSystemAdapter.ts:224-263); an adapter can buffer them into one PUT; not crash-atomic. (c) Reusing the whole shell: ~35 routes. Deploy is outside the topology transport: `host.topoViewer.runLifecycle` -> our code -> manager's existing preview/confirm; feedback via `lab-lifecycle-log/status` window messages (host/index.ts:232-246,353-355).

4. HOST ABSTRACTION. `ClabUiHost` = postMessage/subscribe + explorer + images? + topoViewer (17 methods) + topology{requestSnapshot,dispatchCommand} (host/contracts.ts:186-207). Injection is by prop: `<App runtime={...}>` wraps `ClabUiRuntimeProvider` (App.tsx:69-87; hooks runtimeContext.tsx:50-64); factories let each surface be overridden (host/index.ts:54-63,617-725). INTEGRATORS.md:246-251 documents a custom host as supported ("Pattern C"); :23-29 says the embedder owns auth, files, sessions, lifecycle. Web: createApiClabUiHost + local command dispatcher (standaloneApp.tsx:1274-1345). Desktop: Electron embeds the same Fastify BFF on 127.0.0.1 (apps/desktop/src/main.ts:623-646). VS Code: createWindowClabUiHost in the webview, TopologyHostCore over Node fs in the extension host (ReactTopoViewerProvider.ts:324-335; shared/io.ts:10-53). One engine, three placements.

5. CLAB-API-SERVER. Auth: PAM service `login` plus group check (`clab_admins` hard-coded, else API_USER_GROUP) (API/internal/auth/credentials.go:15,35,55,67-101) -> HS256 JWT, Bearer on /api/v1 (auth.go:114-170; api/middleware.go:71-96). Execution: root (install.sh:217-218; README:91), containerlab v0.79.0 embedded as a Go library (go.mod:18); owner attribution by rewriting process-wide SUDO_USER/USER under a global mutex (internal/clab/service.go:59-62,101-135). Storage: `~/.clab` or `$CLAB_LABS_ROOT/<user>/`, optional `@shared`; relative paths only (api/helpers.go:621-648; workspace_files_handlers.go:30-50). Multi-user: owner-label filter, 404 concealment, superuser bypass (lab_handlers.go:1028-1070; helpers.go:295-307). No audit log (grep "audit": 0 hits). Conflicts: a second lifecycle authority whose locks the manager's flock/operation_busy cannot see (MGR host_operations.py:235,264,322-325); storage disjoint from trusted roots /etc/containerlab and /srv/.../projects (MGR/deploy/setup-operations.sh:31); root daemon + socket + own login versus the manager's no-login, no-socket rules (MGR/CLAUDE.md:142); the manager's engineer account is in clab_admins, hence API superuser (setup-engineer-access.sh:45-46); actions bypass the manager event log (main.py:105-115); duplicate terminals and capture. Related manager fact: the VM helper can only create-new, delete or read YAML, never overwrite, `.yaml/.yml` only (host_operations.py:210-213,283-285); VM YAML editing was removed on purpose (MGR/agent instructions.md:734-735).

6. STANDALONE-RUNTIME. Private, source-exported React app shell for web and desktop. Build flag VITE_CLAB_RUNTIME_MODE=pages gives the GitHub Pages sandbox: it monkeypatches window.fetch and EventSource, stores files in localStorage, runs TopologySessionCore in-browser and answers 501 for runtime/lifecycle (pagesSandboxRuntime.ts:637-642,870-872,1108-1125; CA/README.md:22). It is a working editor-without-backend, but a poor base: not on npm, needs the pnpm/Node 24 monorepo build, no injection seam (PagesSandboxApi not exported, :627,1114), its fetch shim swallows every same-origin /api/* call in that document, and it drags the whole shell. Re-creating its ~90 relevant lines on public clab-ui exports is cheaper.

CONSTRAINTS. Manager headers: style-src 'self', default-src 'self', X-Frame-Options DENY (MGR/clab-backup-ui/app/main.py:116-123); rule "no build step, no framework" (MGR/CLAUDE.md:115,142). MUI/emotion/Monaco under that CSP was not tested.

Not tested in a browser; a per-page CSP exception like the existing xterm one is probably required, and an iframe to a sidecar on another port is blocked by default-src 'self'.
- Which owner label do labs deployed by the manager's sudo helper carry (SUDO_USER under the clab-discovery forced command)? That decides whether ordinary clab-api-server users would see them or get 404. Not verified; no lab was touched.

- Bundle size and load cost of a browser build containing App plus TopologySessionCore (yaml, ajv, elkjs, maplibre-gl, monaco are dependencies). Nothing was built; only the unpacked package size is known (dist 4.2 MB, dist-viewer 21 MB).
