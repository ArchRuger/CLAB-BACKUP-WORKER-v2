Packet capture setup

Stream packets from a lab interface to desktop Wireshark. The optional Edgeshark services run on your Linux lab host; the Wireshark plugin runs on your workstation.

1. Start or reuse Edgeshark

If you already installed Edgeshark through the Containerlab VS Code extension, reuse it. For a new installation, run from this repository's root on the lab VM:

sudo docker compose -f deploy/compose.capture.yml up -d
curl --fail http://127.0.0.1:5001/version
curl --fail http://127.0.0.1:5001/discover/mobyshark

The supplied services bind to localhost and use pinned images. They need host namespace privileges, which stay outside the manager container. Keep packet capture access on a trusted management network or use the tunnel below.

2. Enable the manager provider

Add or update these entries in clab-backup-ui/.env, retaining the rest of that file:

CAPTURE_PROVIDER=edgeshark
CAPTURE_EDGESHARK_URL=http://127.0.0.1:5001
CAPTURE_EDGESHARK_PUBLIC_URL=http://127.0.0.1:5001

The first URL is reached by the manager; the public URL is reached by desktop Wireshark. Both must refer to the same Edgeshark instance. Upgrade the complete source using bash deploy/install.sh. If the manager is already on version 1.20.0, apply changed settings with:

sudo docker compose --env-file clab-backup-ui/.env \
  -f clab-backup-ui/compose.yml up -d --no-deps backup-ui

For image deployment, use these variables in the existing deploy/image.env and recreate through deploy/compose.image.yml. Preserve the data volume and encryption key.

3. Install the desktop plugin

Install Wireshark and Siemens cshargextcap. On Windows, run the EXE installer from the Windows amd64 ZIP. Restart Wireshark and check that Docker host capture appears in the capture interface list. On Linux or macOS follow the upstream platform instructions; macOS also needs the separate URL handler. Avoid Wireshark 4.4.0, which upstream identifies as incompatible.

4. Connect the workstation

For the localhost deployment, keep this command running in a workstation terminal. Replace the account and host with your normal VM login:

ssh -N -L 127.0.0.1:5001:127.0.0.1:5001 your-linux-user@your-lab-vm

Use your regular Linux account, not the restricted clab-discovery account. Verify the Edgeshark page at http://127.0.0.1:5001 on this workstation. If this local port is busy, change the first port in the tunnel and the manager's public URL together. A directly reachable, protected Edgeshark service can use its host URL instead.

5. Capture

Open Capture packets, use a node's Capture action, or click a topology link. On a link, choose either endpoint. Select a target and one or more live Linux interfaces, then Prepare capture → Open Wireshark. Accept your browser's external-app prompt. Stop and save the PCAPNG file in Wireshark.

All host targets includes host NICs, bridges and other namespaces, even when they are absent from the topology drawing. Search by target or interface name. A NOS port alias can differ from its Linux name; select the actual interface instead of assuming the displayed alias. Interfaces reported DOWN and stopped containers are unavailable. VM-internal traffic may require capture inside the guest or platform-specific mirroring.

If something fails

  • Disabled: check the variables and recreate the manager.
  • Discovery unavailable: check the VM-side URL, both service logs, TLS trust and port conflicts.
  • No node match: choose All host targets and select the namespace explicitly.
  • Target changed: refresh and select again after a node or manager restart.
  • No desktop app opens: check the plugin, packetflix URL handler and browser prompt.
  • Wireshark cannot connect: check the workstation URL and SSH tunnel. Browser login cookies are not automatically available to the plugin.
  • No packets: check the selected endpoint, generate expected traffic, and consider guest/host interface visibility.

The manager can prepare the handoff but cannot confirm that a native application opened or that capture is running. Closing this page does not stop Wireshark. Capture files are saved on your workstation and do not enter backup or Git history.

Disable or remove

Set CAPTURE_PROVIDER=disabled and recreate the manager. Stop active sessions in Wireshark. To remove only the optional services from this repository:

sudo docker compose -f deploy/compose.capture.yml down

Disabling the manager provider does not revoke direct Edgeshark access. See CAPTURE.md in the source checkout for architecture, maintenance, research and live acceptance checks.
