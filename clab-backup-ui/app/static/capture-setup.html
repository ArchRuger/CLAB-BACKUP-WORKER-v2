Packet capture setup and troubleshooting

For administrators. Wireshark runs on the lab VM and opens in the student's browser; nothing is installed on the workstation — no plugin, VNC client or capture-port tunnel.

1. The VM services

The browser capture stack is part of every installation: bash "$HOME/projects/clab-manager/deploy/install.sh" installs it and every later install or upgrade refreshes it. To reinstall or repair only this stack, run from any directory on the VM:

sudo bash "$HOME/projects/clab-manager/deploy/setup-capture.sh"

It pulls the pinned Wireshark image, builds the session service, starts Edgeshark, updates the capture settings while preserving unrelated configuration, and recreates the manager so it loads them. Download active browser captures before upgrading: restarting the service removes temporary sessions.

The bundled stack needs free localhost ports 5001 and 5801. Setup does not remove another tool's Edgeshark installation; resolve conflicts first. Keep the manager on a trusted management network or use an authenticated HTTPS reverse proxy with WebSocket support.

2. Capture in the browser

Students open Capture traffic… from a device, a link on the map or Tools › Packet capture. The dialog lists the device's connected interfaces first; Start capture → Open Wireshark ↗ opens the viewer in a new tab. On a link either end can be chosen. Everything on the VM under Advanced includes host NICs, bridges and other namespaces.

3. Save, download and end

Stop capturing in Wireshark, then use File → Save As under /pcaps with the full file name ending in .pcapng. Download saved captures hands over a .tar archive with the PCAPNG files. End session deletes the container and its files.

Four sessions can run at once. A closed viewer stays available for 15 minutes under Your capture sessions. Every session ends after two hours. The capture folder holds 256 MiB. Save and download before expiry; capture files never enter backups or Git history.

Troubleshooting

  • "Packet capture is not set up on this VM": run setup, recreate the manager and check the service logs below.
  • Disconnected from Wireshark: Reconnect viewer joins the existing session; the capture may still be running.
  • Session not found: it may have ended, expired or belong to another browser profile.
  • No matching interface: choose Everything on the VM and pick the Linux interface name; device port names (ge-0/0/0) often map to eth1, eth2…
  • Download reports no saved captures: stop the capture in Wireshark, use File → Save As under /pcaps, then download again; the archive only holds that folder.
  • No packets: check the endpoint and generate traffic. DOWN interfaces, stopped containers and traffic hidden inside nested VMs remain outside exposed Linux interfaces.
sudo docker compose --env-file "$HOME/projects/clab-manager/clab-backup-ui/.env" -f "$HOME/projects/clab-manager/deploy/compose.capture.yml" ps
sudo docker compose --env-file "$HOME/projects/clab-manager/clab-backup-ui/.env" -f "$HOME/projects/clab-manager/deploy/compose.capture.yml" logs --tail=80 sessions
bash "$HOME/projects/clab-manager/deploy/check-install.sh"
