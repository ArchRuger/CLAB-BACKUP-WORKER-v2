      Import a lab from an Ansible inventory

      Upload the ansible-inventory.yml that containerlab generates next to the lab. It lists every device and its management address.

      YAML or JSON · up to 1 MiB
      Optional: topology-data.json

      Only needed when the inventory does not say what kind of device each node is.

      Add login credentials

      The username and password (or SSH key) used to log in to the device CLI.

      Arista EOS enters enable mode before reading the configuration. Leave blank if the account does not need it.

      Connection

      Use a short name such as GTW-1 when the full name carries a long lab prefix. New backups use it.

      Automatic uses the management address the running lab reports and port 22. Manual keeps the address you type. Automatic is available once this lab is linked to a running lab.

      Advanced

      Import the lab map

      Saved by the containerlab VS Code extension next to your lab's .clab.yaml — it holds device positions, groups and notes.

      Include it to draw the links between devices.

      Importing replaces the current map. Device connections and credentials are not affected.

      Export sessions for SuperPuTTY

      One folder for this lab, with a session for every device using its saved SSH address and port. Your computer must be able to reach those addresses.

      Saved credentials are used; otherwise the device's default username.

      Without passwords, PuTTY asks when you log in. SSH keys are never exported.
