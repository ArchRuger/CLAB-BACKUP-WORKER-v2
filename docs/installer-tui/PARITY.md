# Installer parity: plain menu and full-screen installer (Slate Ops)

Every installer action and option, the TUI control that carries it, the callable behind it, and the test that
holds it. The plain menu (`deploy/install-manager.py`) is the reference; the full-screen installer
(`deploy/installer_tui/`) reuses its plan, helper commands and recovery rules (`action_steps`, `install_steps`,
`plan_lines`, `Options`) and decides only how each phase meets the terminal (`engine.py`).

Legend. A bare test name is a test method; `Class.*` means every test in that class.
- `IM` = `clab-backup-ui/tests/test_install_manager.py` (unit, system `python3`).
- `CORE` = `clab-backup-ui/tests/test_install_tui_core.py` (unit, system `python3`, real subprocesses with tiny scripts).
- `APP` = `clab-backup-ui/tests/test_install_tui_app.py` (headless Textual; skipped without Textual unless `INSTALLER_TUI_REQUIRED=1`).
- `PTY:<scenario>` = `docs/installer-tui/tools/pty_check.py` against a fake-helper fixture in tmux (`hangup`, `stop`, `flood`, `interrupt`, `lock`; output in `evidence/pty-check.txt`).
- `Live Ln` = a row of the dev-VM runs in [VALIDATION.md](VALIDATION.md) (L1 `--setup-tui`, L2 first install, L3 stalled pull and retry, L4 Git cancelled, L5 `sudo -v` refused, L6 health check, L7 update with sentinel lab, L8 second invocation refused, L9 real dpkg lock, L10 disposable sudo account).
- **GAP** = no test pins it. The consolidated list is section 8.

The invariant audit (`invariants-report.md`) was reconciled against this page; its items that this page did not carry
are in section 9.

## 3. Install phases and how each meets the terminal in the TUI

The plain menu runs every phase on the real terminal except the package step (tee, to spot the lock signature).
The TUI runs a phase piped with `sudo -n` (`core.noninteractive`, `core.StepProcess`) unless it needs the terminal.

## 7. Installer lock and documented intentional differences
