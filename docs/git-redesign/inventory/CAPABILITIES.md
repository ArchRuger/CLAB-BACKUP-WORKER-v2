# Git save and load redesign: inventory of today's capabilities

Acceptance artifact for `docs/git-redesign/PROMPT.md` sections 4 and 5.11. Every row below must have a new home when the project ends; the last column is filled by the lead.

- Base: branch `claude/git-save-load-redesign`, HEAD `513a2b2`, release `1.30.60`. Citations are `file:line` in `clab-backup-ui/app/static/` unless a path is given; backend lines are in `clab-backup-ui/app/`. The cited files had no uncommitted changes when this was written (`git status --short` showed only the untracked `docs/git-redesign/tools/`).
- Method: read `index.html`, `git-progress.js`, `git-places.js`, `restore.js`, `app.js`, `shell.js`, `home.js`, `status.js`, `diff-view.js`, the Git/restore parts of `operations.js`, and the `install()` route tables of `git_progress.py` and `restore.py`. Scripts used (scratch, not committed): a handler/`data-*` extractor and a route extractor (acceptance checks, section 3), a reference scanner over tracked files (Appendix A), a test-name locator and a test counter (tests column, Appendix B). Nothing was executed against a manager, a browser or a VM; every statement is from reading the source.
- Tests column: `GPU` = `tests/test_git_progress_ui.js`, `GPL` = `test_git_places_ui.js`, `RUI` = `test_restore_ui.js`, `HUI` = `test_home_ui.js`, `SUI` = `test_shell_ui.js`, `STU` = `test_status_ui.js`, `RDY` = `test_readiness_ui.js`, `DVU` = `test_diff_view_ui.js`, `GP` = `test_git_progress.py`, `RS` = `test_restore.py`. `GPU:134` is the `test(...)` declaration at that line. "no UI test" lists what was searched. Backend tests exercise the routes, not the controls. A test cited is one whose title or body names the behaviour; this inventory did not run any test.
- `refresh()` (GET `/api/state`, main.py:213) follows almost every action and re-renders the tab, banner and header; it is not repeated in each row. `opTask` (operations.js:23) wraps every click: a failure goes to the dialog’s error line or, with no dialog, to the lab banner (`showActionError`, row "failed header/menu action").
- Surface letters: **H** header save menu, **P** Progress tab, **F** folder browser, **B** lab banner, **M** home card. A row reachable from several surfaces lists all of them; the dialogs shared by several entry points appear once.

## 5. Notes and surprises (facts from reading, none tested)

1. **Dead binding.** git-progress.js:305 binds `[data-git-job]` buttons inside `#git-repository-content`, but the Recent saves rows are rendered into `#git-saves-list` (index.html:145), outside it; the live handler is the delegated click at :793.
2. **Other banner variants are out of scope.** The lab banner also carries Start lab, operation output/Try again, credentials, VM connection, unlinked-lab, design read-back and retired-telemetry cases (app.js:220-251); only the restore, Git-problem, save-attention and action-error cases are rows above.
3. **A failed read looks like "nothing saved".** `gitFetchHistory` and `gitFetchTree` return `false` on failure (git-progress.js:231-232) and the comment promises a *Try again* in the versions list, but `gitRenderVersions` has no such button: with both reads failed `gitVersionGroups` returns empty groups and the Latest group shows "You haven't saved this lab yet." (git-progress.js:377-389).
4. **Folder browser has a read-only mode nobody uses.** `options.canAct===false` hides every action (git-places.js:156, 193); no caller passes it.
5. **No control sends a `backup` restore source** and nothing calls `GET /restore/sources` (section 3(b)); the Devices/Tools backup lists have no Apply.
6. **The header menu is a subset.** It offers Create checkpoint…, Save on this VM only, Saved versions & history, Save location settings…; *Upload saved progress*, *Update from the repository*, *Set baseline…* and *Load a saved version…* exist only on the Progress tab (More menu), *Disconnect* and *Update* also in Advanced repository details.
7. **Home shows less than the header.** `homeSavedLine` calls `progressState` without the `problem` argument (home.js:8), so a broken save location is invisible on a Home card while the header and the banner show it.
8. **No link from Home or the lab banner to the Progress tab by URL.** Banner actions call functions (`gitOpenRepository`, `gitShowJob`, `restoreShowJob`), not a link; the `view=progress` hash is written by `syncRoute`/`writeRoute` after a tab click (app.js:346, shell.js) and read back by `applyRoute` (SUI:73).
9. **A running save is not a lab banner.** `renderLabBanner` has no branch for an active Git job (app.js:220-243): a save in progress shows only in the header status line, `#worker-state` and the status card; `review_pending` and `committed` produce no banner at all.
10. **`gitSaveOptions` default branch.** `gitRunAction` sends any unknown action to `gitSaveOptions` (git-progress.js:780), which labels it "Save progress"; no markup uses it.
11. **Backend and deploy text names the tab.** git_progress.py:291 and :691, deploy/scaffold-lab.py (lines 19, 95, 189-192, 249), deploy/setup-git.sh:158 and deploy/git-onboard.py:556 print "Progress › …" to users; ~25 Playwright tools click `#tab-progress` (Appendix A.2).
12. **The exposure acknowledgement is asked in three places** (binding form, first-save dialog, connect dialog); each has its own constant check (git-progress.js:10-11, 299, 496, 522).
