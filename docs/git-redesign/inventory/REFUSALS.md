## 5. Why folders may not overlap today (quoted)

Search: `grep -n overlap` in `agent instructions.md`, `app/host_git.py` and `app/git_progress.py`, then the deploy scripts, the guides and the browser scripts. **Result: no passage gives a technical reason for the overlap rule.** Every passage states the rule ("cannot overlap", "by design", "cannot be registered beside it"); none says what would break. Facts a design can build on: (a) `GitRepository.scope`/`clean` act on `<prefix>/latest|baseline|checkpoints` only (quoted at the end), (b) `base_prefix` gives a reason only for the *reserved names* rule (a lab folder named `latest` would make the next save create `working/latest/latest`).

## 7. Findings worth knowing

- The refusal quoted in PROMPT 6.1 is raised in **three** places with the same rule (`check_overlap` host_git.py:990 for `register-prefix` and `connect`, the re-check under the lock in `save_registration` host_git.py:1083, and the embedded registration of `deploy/setup-git.sh:104`) and is **mirrored** by the manager's own one-registration-per-lab checks (git_progress.py:1055, 1158, 1254), by its rule 2 (git_progress.py:1009) and by the browser's `gitFolderChoice` / `gitCanCreateIn` (git-places.js). Removing the helper rule alone leaves the browser disabling the same choices, and the browser can contradict itself (`This folder is inside another lab folder.` versus `This lab folder is free — no lab saves here yet.` for a root registration no lab owns).
- `host_git.py` has no `fail(` function; all 162 helper refusals are `raise ValueError`. `main()` prints them as `{'error': ...}` (host_git.py:1162). The manager cuts them to 600 characters (git_progress.py:356, 581).
- `deploy/git-onboard.py` has **no overlap check of its own**: it avoids the root only by prose (comment at 359-362, message at 369) and relies on the embedded registration of `setup-git.sh:104` to refuse later. A repository new to the manager is registered at its root by design (docs/GIT-SETUP.md:55-58): that is the origin of the PROMPT 6.1 dead end.
- `git_progress.py:1332` (`Give this save a short label.`, HTTP 400) and `git-progress.js:85` refuse an empty save note; D2 (optional label) changes this V row, and `host_git.py:526` (`Use a short single-line commit note.`) must accept the manager-written automatic label.
- The folder panel's primary button is disabled by `gitFolderChoice` with the *reason as its `title`* and as the right-hand footer line (git-places.js:156, 161): a person sees a greyed button plus a line, never a toast. A path typed in the first-save dialog or in connect-by-URL goes straight to the server (`POST .../folders`, `PUT .../git`), so the same rules appear there as an HTTP 409 in the dialog's `.form-error`.
- Two refusals depend on lab state, not on the folder: `guard_pending` (git_progress.py:610) blocks folder moves, reconnects and disconnects while a save of this lab waits (PROMPT 6.2 turns it into an inline choice) and `guard_siblings` (git_progress.py:638, 1462, `sibling_refusal`) blocks a save or upload while another lab of the same checkout has an unreviewed save. The second is a checkout-level rule, not in PROMPT 6.2's table; it stays unless the design changes how unreviewed commits are tracked.
- Restore refusals (section C) never mention folders. Per-device reasons are shown twice: translated by the label map in restore.js:40-51 and raw under Details (restore.js:197). `restore.py:683` lists up to six `name: reason` pairs, so one device's reason can appear inside an HTTP 409 text at submit.
- `tests/test_git_progress.py:1127-1133` holds a second copy of the overlap text in a fake helper (a fixture, not a pin of the real helper); the real helper is pinned by `tests/test_host_git.py:675-704, 874`. The fixture manager's `FakeGit` (PROMPT 6.4) is not in this inventory.
