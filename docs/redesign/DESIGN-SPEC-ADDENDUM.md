# Design spec addendum — decisions on the parity and critique findings

This file amends `DESIGN-SPEC.md`. Where the two disagree, this addendum wins. Implementation agents must also read the module's `parity/<module>.md` file: **every "Spec gaps" fix and every microcopy rewrite listed there is accepted and must be applied**, except where a decision below modifies it. `inventory/MERGED-INVENTORY.md` (when present) plus `parity/*.md` together are the regression checklist.

## A. Navigation and shell

1. **Active-lab precedence on load**: `#lab=<id>` in the hash → else `sessionStorage.activeLab` (read once, then `removeItem`; the hash takes over from then on) → else Home. A missing/unknown id falls back to Home. `selectLab(id)` writes the hash (`#lab=<id>&view=<tab>`), sets `sessionStorage.activeLab` (legacy writers in management.js/operations.js keep doing so) and records `localStorage clab.lastLab` + `clab.opened.<id>`. `goHome()` clears `activeId`, the hash and `sessionStorage.activeLab`. `hashchange` re-reads the hash (back button works). `openDetails(name)` adds `&device=<name>`; closing the drawer removes it.
2. **Tab normalisation**: `const TAB_ALIAS={inventory:'devices',git:'progress',backups:'tools',credentials:'advanced',logs:'advanced'}` and `SUBVIEW={inventory:'technical',backups:'backups',credentials:'credentials',logs:'logs'}`. `showTab(value)` sets `tab=TAB_ALIAS[value]||value` and `subview=SUBVIEW[value]||''`; `render()` normalises `tab` the same way so legacy direct assignments (`tab='inventory'` in management.js, `'backups'` in startJob) still resolve. The logs poll condition becomes `tab==='advanced'&&subview==='logs'`. Post-import/post-deploy success paths call `selectLab(id)`; lab removal (when active) and Start fresh call `goHome()`.
3. **No duplicate ids — proxy pattern**: a control that must appear in two places has one owner element (keeps its id and all existing bindings) and any number of `button[data-proxy="<id>"]` mirrors. `app.js` provides `syncProxies()` (called at the end of `render()`): copies `disabled`, `title`, `hidden` and text-independent state from the owner; a disabled mirror inside a `.menu-list` gets `<small class="menu-reason">` with the owner's `title`. Mirror click → `$(id).click()`. Owners: `#remove-lab` (Advanced › Danger zone), `#lab-actions` (Advanced › Lab operations, declared statically in index.html; operations.js only injects it when absent), `#sync-vm` (Advanced › Deployment details next to `#vm-files-status`), `#map-ssh-all` (map More ▾), `#map-backup-all` (map More ▾), `#operations-history` (Manager ▾), `#link-deployment` (Advanced). Lab actions ▾ items and Tools cards are mirrors.
4. **Labels must survive async resets**: any handler that writes a busy label captures the idle label first (`const label=button.textContent`) and restores it, never a literal (management.js `vm-refresh`, `sync-vm`).
5. **innerHTML diffing**: `setMarkup(el, html)` helper in app.js (assign only when `el._markup!==html`); use it for every list that re-renders on the 4 s poll (`#discovered-labs`, `#excluded-labs`, `#discovery-file-list`, `#empty-discovered-list`, `#lab-cards`, `#device-list`, `#topology-devices`, `#details-info`, banner).
6. **Removed elements that code still writes**: keep `#app-version`, `#supported-release` (Manager ▾ footer: "Containerlab Node Manager v1.29.0 · Works with Junos, IOS-XR and Arista EOS"), `#updated` (Advanced › Technical details "Lab record updated"). Delete `#subtitle` and its writes. Empty state gets the caption "Works with Junos, IOS-XR and Arista EOS" instead of pills.
7. **Deploy a new lab**: Home `#home-deploy` and Manager ▾ "Deploy a new lab…" both call `openDeploy()` (in-page browser, gated on VM connected with the reason as `title` and inline caption). The full-page browser stays reachable as Manager ▾ "Lab topology browser (full page) ↗" = `#vm-projects` (unchanged navigation). `#home-import` → `openSetup()`; `#home-import-inventory` → `openImport()`; home.js never binds `#new-lab`/`#import-empty`/`#import-top`.
8. **Other labs on the VM** (`#home-discovered`): shown whenever discovery lists a non-imported lab or `ignored_labs` is non-empty, regardless of lab count. Excluded rows get a visible `[Stop hiding]` button (`data-clear-exclusion`, delegated on `#excluded-labs` → `openExclusionMenu`); right-click/Shift+F10 paths stay.
9. **Home VM banner** `#home-vm-banner.banner.warn`: rendered by `renderLanding()` when the VM is unconfigured/unreachable/paused, with [Connect the VM] / [VM connection…] → `openVmDialog()`.
10. **Worker/activity indicator** `#worker-state`: text from job kind — git busy "Saving progress…", restore busy "Replacing configuration…", backup running "Backing up…", automatic/manual test "Checking device logins…", operation "Lab operation running…"; hidden when idle. `busy()` semantics unchanged; the restore source is `state.restore_jobs` (already in `/api/state`).
11. **Lab-less operations** (`inspect-all`, browse/deploy from the dialog): `#operation-summary` lives in `#home-banner` on Home and in the lab banner on a lab page (same element, moved by CSS/DOM position: keep ONE element in the top-level page area above both `#home` and `#lab-content`).
12. **Lab switcher** sub-text: `labState(lab).label` + "n of m devices ready" — never the raw deployment status.
13. **Lab card / home context menu**: right-click or Shift+F10 on a card opens `openLabOperations(id)` (generalise the `#labs` binding to `#home`).
14. **Escape priority** (one document handler chain): node context menu → any open `details.menu` → expanded map.
15. **Menus**: `details.menu` closes on outside click and Escape via `closeMenus()`; `#git-save-menu` and `#extra-views` (if kept) use the same helper; `summary` carries `aria-haspopup="menu"`, the list `role="menu"`, items `role="menuitem"`; Arrow keys move focus (reuse the node-menu pattern).
16. **Danger styling**: `#manager-reset`, the remove-lab submit, destroy/redeploy-cleanup confirm buttons, restore confirm, disconnect confirm are `.button.danger`.
