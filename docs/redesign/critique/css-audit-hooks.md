## Method

Script: `/tmp/claude-1000/-home-clabllm/58f9753c-3287-4bf9-9f68-d2da708ca22e/scratchpad/hook_audit.py` (raw results in `critique/hook_audit_raw.json`, full per-hook index in `critique/hook_audit_index.json`).

1. Parsed every selector of the old and new sheets (comments stripped, `@media` unwrapped, `:not()`/`:has()` arguments excluded so a class that only appears inside a negation does not count as styled).
2. Collected hooks from all 11 `.html` and 16 `.js` files in `app/static/`: `class="…"` (HTML and template literals, string literals inside `${}` included), `classList.add/remove/toggle/contains`, `className=`, `querySelector*/closest/matches` selector strings, `id="…"`, `getElementById`, `$('…')`, `setAttribute('class'|'id')`, plus the dynamic `$(name+'-view')` family. Result: **218 class names, 335 ids**.
3. Flagged any hook that had a rule in the old sheet and has no selector mentioning it in the new sheet, then hand-checked the DOM context of every compound selector against the real markup (index.html read in full; JS emission sites read for the drawer, node table, jobs, git-places, git-progress, restore, operations, diagram editor, capture, topology renderer; every standalone page read in full).
4. Verified the seven items the brief named, the `!important` set, brace balance, `var()` definitions and keyframe references.

## Behavioural regressions

1. **≤900px: the legacy More ▾ tab menu is clipped.** `@media (max-width:900px) .tabs {overflow-x:auto; overflow-y:hidden; flex-wrap:nowrap}` (2161). In the current markup `details#extra-views.extra-views{position:relative}` sits *inside* `nav.tabs`, and its `.extra-views-menu` is `position:absolute; top:100%`. A scroll container clips absolutely positioned descendants whose containing block is inside it, so below 900px the Credentials / Action logs menu is cut off (the old sheet's final ≤760 block re-set `.tabs{flex-wrap:wrap; overflow:visible}` precisely to avoid this, css.md §3.1). Spec §3 "tabs scroll horizontally at 900" was written for the new `role=tablist` strip that has no dropdown. Fix: `@media (max-width:900px) .tabs:has(.extra-views[open]) {overflow:visible}` (or keep `.control-row .tabs{flex-wrap:wrap; overflow:visible}` until the tablist markup lands).
2. **Activity indicator pulses while idle.** `.worker-state::before{animation:pill-pulse 1.4s infinite}` (321–329) is unconditional and `.worker-state:empty{display:none}` never fires because app.js:45 still writes `'Worker idle'`. Until app.js hides the idle text, the top bar shows a pulsing accent dot beside "Worker idle" — the opposite of the spec's "hidden when idle". Fix: animate only in a busy state (`.worker-state.busy::before` / `[data-busy="true"]`) and set that from `render()`, or `animation:none` on the base pseudo-element for now.
3. **`.capture-hit` narrowed to `role="button"` wires** (1554). `topologyLink()` (topology-render.js:31–39) always emits `captureAttrs` (incl. `role="button"`) on every `.topology-wire`, so nothing breaks today, but the old `path.capture-hit` contract was unconditional: any wire rendered without the role (a future non-interactive preview, or a renderer change per addendum C) would paint the hit path as a second 2px wire (from `.topology-wire path`) and lose the 16px hit area. Fix: keep `path.capture-hit{stroke:transparent;stroke-width:16;pointer-events:stroke}` unscoped and scope only the `:hover/:focus-visible path:not(.capture-hit)` rule.

Not regressions, verified: `body{display:grid}` on all pages; the generic `dialog :where(label:not(.checkbox-label))` rule is out-ranked wherever a component needs it (`.capture-interface`, `.capture-controls label`, `.diagram-properties label`, `.op-coordinates label`); `.node-context-menu button:focus{outline:none}` is followed by a `:focus-visible` ring (703), so keyboard focus is now visible; `.table-wrap thead th{position:sticky}` only takes effect inside the 65vh logs wrapper (the node table's wrapper never scrolls vertically) and is switched off ≤760; `.dialog-actions .danger/.danger-outline{order:10}` moves danger buttons rightmost as spec §3 asks; `.git-save-control:has()` still has no fallback (same as before).
