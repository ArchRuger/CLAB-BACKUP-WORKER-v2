### How the JS harnesses work (common pattern)

Every file uses `node:test` + `node:assert/strict` and loads the **production** file(s) with `fs.readFileSync(path.join(__dirname,'../app/static/<name>.js'))` into a `vm.createContext({...})`, then `vm.runInContext(source, context)`. Nothing is bundled or transpiled, so:

* Every production script must remain a **plain classic script whose top-level `function` declarations and `let`/`const`/`var` bindings are reachable as context globals** (tests call `context.refreshCaptureTargets()`, `vm.runInContext("captureLab='lab'", c)`, `context.state.git_jobs=...`, `context.json=...`, `context.gitLoadContext=...`). ES modules, IIFE wrapping, bundling or renaming these functions breaks every test.
* Cross-file globals are stubbed by the harness, which fixes the **public contract between files**: `$`, `esc`, `api`, `json`, `notify`, `refresh`, `state`, `activeId`, `current`, `busy`, `utcDisplay`, `platformLabel`, `opDialog`, `opTask`, `opNewTab`, `withForm`, `openImport`, `openDeploy`, `closeNodeMenu`, `map`, `tab`, `gitLoadContext`, `gitShowRepository`, `gitShowJob`, `gitViewVersion`, `gitOpenRepository`, `gitSubmitSave`, `opBrowse`.
* The fake DOM is minimal: `document.getElementById` returns an auto-created stub object keyed by id (so **every element id below is a hard contract**); handlers are read back as `el.onclick`, `el.onsubmit`, `el.onchange`, `el.ontoggle`, or from `el.listeners[event]` captured by a stub `addEventListener` (one listener per event name per element — a second `addEventListener('click')` on `jobs` or `nodes` would overwrite the first in the harness). `showModal()`/`close()` set `open`; `close()` in the capture harness fires `listeners.close`.
* Markup is asserted with regexes on `innerHTML` strings; those regexes (attribute order, spacing, exact labels) are listed per test below.
* Timers are stubbed (`setTimeout` runs immediately, or is recorded, or returns 0) so polling behaviour is asserted through the recorded callbacks.
* `sessionStorage` is a Map stub in `test_download_ui.js`, `test_readiness_ui.js`, `test_git_progress_ui.js`, `test_operations_ui.js` (opSaveWorkspace); the only key asserted by name is **`activeLab`**.

Legend for classification: **behavioral** = asserts on function results / requests / state, independent of HTML; **markup** = asserts on incidental HTML; **mixed** = protects a behaviour but pins it through markup regexes, ids-in-innerHTML, class names or exact label text.
