# Merged functional inventory — clab-manager web UI (release 1.28.0)

Regression checklist for the UI redesign. Merged and deduplicated from the per-module inventories in this folder (shell, management, operations, git-progress, git-places-restore, topology, capture, pages, css, tests, vocabulary, docs). One row per distinct capability: where a button appears in several places but runs the same code path (e.g. the node SSH/Back up/Capture/Details actions in the table, the details drawer and the map context menu, all dispatched by `handleNodeAction`), it is one row listing every trigger location. Different behaviours are kept as separate rows even when their labels match.

Rows: 134 capabilities, 52 cross-file globals. Test references use the numbering of `tests.md` (`test_capture_ui.js#3` = third `test()` block in `clab-backup-ui/tests/test_capture_ui.js`). Relevance: primary = a student uses it in a normal lab session; secondary = occasionally; advanced = instructor/operator.

## 3. Load-order overrides to preserve

- management.js re-assigns `onclick` after app.js for `#new-lab`, `#import-empty` (→ `openSetup()`), `#import-top` (→ lab ? `openImport(true)` : `openDeploy()`), `#map-ssh-all`, `#map-backup-all`.
- operations.js wires `#map-edit`, `#deploy-empty`, `#lab-actions`, `#vm-projects`, `#lab-start`, `#lab-destroy`, `#operations-history`, `#inspect-all` and the `#labs` context-menu/keyboard handlers only when `#import-top` exists; it injects `#lab-actions` before `#import-top`.
- app.js `render()` calls `renderManagement()` → `renderLabOperations()` → `renderGitProgress()` in that order; busy-state disabling of `#remove-lab`/`#sync-vm` depends on it.
- Cross-file calls guarded with `typeof … === "function"`: renderManagement, renderLabOperations, renderGitProgress, refreshMap, gitShowRepository, captureActionAttrs, sshHint, restoreFromFolder, restoreFromVersion. Unguarded: openCapture (app.js), opDialog/opTask (all consumers), topologyMarkup/measureTopology, editDiagram, map/closeNodeMenu (capture.js).
