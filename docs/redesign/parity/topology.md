# Parity review — topology module (map, renderer, diagram editor)

Reviewed against: `DESIGN-SPEC.md` (§0, §1.3 Topology/Tools/Advanced, §1.4, §2, §3 Map, §4), `UX-AUDIT.md`, `inventory/topology.md` (every row), `inventory/css.md` §20, `inventory/tests.md` §2/§4/§10/§12/§14, the live sources `topology.js`, `topology-render.js`, `diagram-editor.js`, the consumers in `app.js`, `capture.js`, `management.js`, `operations.js`, `index.html`, `style.css`, backend `topology.py bind_drawing`, and screenshots 01 (1920/1366, full), 16, 17, 19, 20.

## Verdict

The spec gives the map the right place (the Topology tab *is* the map, tools become an overlay, the right-click menu is relabelled in the right order, Export sessions goes to Tools). Nothing in this module is dropped. But four placements would break behaviour if implemented as written, and the spec leaves almost all of this module's microcopy untouched even though §0.5 makes rewriting it mandatory:

1. **State dots cannot come from `topology-render.js`** (GAP A). `/topology` carries no readiness (`bind_drawing` adds only `inventory_name`), the renderer cannot see `current().nodes`, and `refreshMap` rebuilds the SVG only when the drawing JSON changes — dots would freeze at first paint and acceptance check 2 ("map dots turn green") fails. Needs a class-toggling `applyMapStates()` on the poll.
2. **`#topology-map` "surface bg, subtle dot grid" contradicts the renderer**, which paints the imported cream background inside the SVG (GAP B).
3. **Tools › "Open all CLIs" own button loses the readiness gate** because `app.js` writes `disabled/title` to `#map-ssh-all` by id (GAP C).
4. **Tools › "Diagram exports" points at buttons that exist only inside the editor dialog** and post its in-memory drawing (GAP D).
5. **The spec misdescribes today's left-click** ("only selected/labelled") — `mapAction` already opens the drawer (GAP I). A lab without a map loses its only obvious Import button (GAP E). `.map-expanded` with the new device rail is undefined (GAP F).
6. **No copy** for the caption, the import dialog, the export dialog, the backup-all review, the disabled-menu reasons or the diagram editor (GAPs G, H, K, L, N, O), and three words — topology / diagram / map — for one object (GAP M).

Rows: 74 · unchanged 40 · moved 3 · renamed 18 · moved+renamed 8 · reorganized 3 · behaviour-changed 2 · UNMAPPED 0 · spec gaps 19. Intentionally removed: **none**.

## Spec gaps (each with a concrete fix)

### render.node-glyph

**Problem.** GAP A — Spec §1.3 says "topology-render.js adds class=\"map-device state-<key>\" and a circle.device-state-dot per node from deviceState(node)". That cannot work as written: (1) the drawing from GET /labs/{id}/topology carries only `inventory_name` (topology.py bind_drawing:204), no readiness; (2) `topologyMarkup(drawing)` has no access to `current().nodes`; (3) `refreshMap` rebuilds the SVG only when the drawing JSON changes (`mapKey` dedupe), so state baked into the markup would freeze at first render and never follow the 4 s poll — acceptance check 2 ("map dots turn green") would fail; (4) `test_topology_ui.js` and workspace.html (`opMapPreview`) load the renderer without status.js, so a hard call to `deviceState` throws.

**Fix.** (1) `topologyMarkup(drawing, states={})` — optional map `{inventory_name: key}`; `topologyNode(n, states)` emits `class="map-device state-${states[n.inventory_name]||'neutral'} …"` and `<circle class="device-state-dot" cx="16" cy="-16" r="5"/>` (does not touch the label offsets asserted by test 2). (2) New `applyMapStates()` in topology.js: for each `[data-map-node]` in `#topology-map`, compute `deviceState(node).key` from `current().nodes` and swap the `state-*` class via `classList` — never innerHTML. (3) app.js `render()` calls `if(typeof applyMapStates==='function')applyMapStates()` after `renderNodes()`; `refreshMap` calls it right after `measureTopology`. (4) `opMapPreview` passes nothing (neutral dots). (5) Tests: `test_topology_ui.js` — markup without states carries `state-neutral` and one `device-state-dot`; `test_shell_ui.js` — `applyMapStates` toggles classes on stub elements and leaves `innerHTML` untouched. Colours stay in CSS as spec §3 says.

### render.background-grid

**Problem.** GAP B — Spec §3 Map: "`#topology-map` (surface bg, subtle dot grid)" is a CSS statement, but the renderer paints a 400000² rect filled with `settings.background` (default `#fdf6e3`, cream) and a grid pattern with `settings.gridColor` inside the SVG, from the imported annotations.
