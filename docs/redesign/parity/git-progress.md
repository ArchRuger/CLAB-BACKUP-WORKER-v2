# Parity review — git-progress.js (Save progress / Git storage) against DESIGN-SPEC.md

Inputs: `inventory/git-progress.md` (80 capability rows, 14 dialogs, 48 microcopy issues), `DESIGN-SPEC.md` §0, §1.1, §1.3 (header, banner, Progress tab), §1.6, §2 (`progressState`), §4 (git-progress.js / git-places.js rows), §5; `UX-AUDIT.md` §2–§3; source `git-progress.js` (320 lines, verified line numbers below); `inventory/tests.md` §6–§7, §14; `inventory/vocabulary.md` §2.21–2.22, §4.7; `inventory/git-places-restore.md`; screenshots `02-tab-git`, `04-git-save-menu`, `05-git-settings-dialog`, `06-git-history-dialog` (1920×1080); memory note `restore-ux-folder-apply` (user: apply must be pick-and-load from any folder, no rebinding).

Verdict in one line: the spec gives almost every capability a home and the relabels are right, but it under-specifies the *mechanics* that keep them working after the move — the three `tab==='git'` checks, the once-at-load id wiring, the `data-git-action` gating loop, the data source for the inline "Saved versions" list, and the folder-first Apply flow — and it mislabels one action ("Compare with current") in a way that would mislead students. Twenty concrete gaps follow the table; none requires a backend change.

Change key: unchanged · moved · renamed · moved+renamed · reorganized · behaviour-changed · UNMAPPED.
Location format: screen › tab › section › control.

## 2. Spec gaps (each one keeps the capability fully working; none touches the backend)

**GAP-A — `data-git-action` duplicates outside `#git-save-menu` (git.save-menu, git.menu.*).** Spec §1.3 puts [Create checkpoint…], [Set baseline…] and a More ▾ (local/push/update/settings) with "the same `data-git-action` values" in the status card. git-progress.js wires clicks (line 317) and applies the activity gating (line 56) only to `$('git-save-menu').querySelectorAll('[data-git-action]')`, and hides only `#git-save-menu` when unbound (line 55). The duplicates would be dead, never disabled during a save, and visible for an unbound lab. Fix: (1) `renderGitProgress()` gates `document.querySelectorAll('[data-git-action]')` with the same exemption list and toggles `hidden` on every `[data-git-action]` container when there is no binding; (2) the init block wires every `[data-git-action]` through `gitRunAction`; (3) `gitRunAction` calls `closeMenus()` so the status-card menu closes too; (4) group the eight header items with `.menu-sep`: [Save on this VM only · Create checkpoint…] | [Saved versions & history · Load a saved version…] | [Upload saved progress · Update from the repository · Set baseline… · Save location settings…]; keep Set baseline inside More ▾ on the status card (it needs a complete backup and is an instructor action), leaving [Save progress] [Create checkpoint…] [More ▾] as the card's row.

**GAP-B — `#progress-save` proxy and disabled-reason (git.save-progress).** "Proxies `#git-save-progress`" is not enough: a `.click()` proxy is silently inert whenever the header button is disabled, and the brief forbids unexplained disabled buttons. Fix: `renderGitProgress()` sets `textContent`, `disabled` and `title` on both `#git-save-progress` and `#progress-save`; the proxy's click calls `opTask(null, gitSaveProgress)` directly. Titles/captions: active save → "Saving… wait for the current save to finish"; `busy()` → "A backup or lab operation is running. Save progress is available when it finishes"; unbound → "Choose where this lab's progress is saved first". The status card shows the reason as a `.caption` under the button.

**GAP-C — `tab==='git'` after the `git→progress` mapping (git.tab, git.job.poll).** Lines 249 (`gitStartWatch` completion → `gitShowRepository(true)`), 255 (`gitDismissJob`) and 266 (`gitUpdateRemote`) compare `tab==='git'`. With `showTab('git')` mapped to `progress`, the Progress tab stops refreshing after a save completes, after Keep snapshot only, and after an update — until the student finds Refresh status (now inside Advanced). Fix: spec §4 git-progress.js row adds "replace the three `tab==='git'` comparisons with `gitTabActive()` → `tab==='progress'||tab==='git'`", and `tests/test_git_progress_ui.js` gets a #14-style test with `tab='progress'` asserting `gitShowRepository(true)` is called on completion.
