# Parity review — management module (management.js + vm-connection.html)

Reviewed against: `DESIGN-SPEC.md` (§0, §1.1–1.6, §2, §4), `UX-AUDIT.md`, `inventory/management.md`, the live sources
`app/static/management.js` (232 lines), `index.html`, the bindings in `app.js` (lines 16, 40–59, 101) and `operations.js`
(lines 181–184, 269–281), `inventory/tests.md` §10/§13/§14, `inventory/vocabulary.md` §1.7/§2.16, and screenshots
`08, 11, 12, 13, 14, 15, 18b, 18c, 01`.

Verdict in one paragraph: the spec gives almost every management capability a home (Manager ▾ menu, Home "Also running on
the VM", Advanced › Deployment details, Lab actions ▾), which is the right IA. But it is under-specified exactly where this
module's behaviour is load-bearing: (1) it assigns `#remove-lab` and `#lab-actions` to two DOM positions each (one copy
would be dead), (2) it changes the gating of `#sync-vm` while claiming "as today", (3) it relabels `#vm-refresh` and
`#sync-vm` although management.js rewrites their `textContent` after every click, so the new labels revert on first use,
(4) it introduces hash routing and `showTab` name mapping but management.js sets `tab='inventory'` and `activeId`
directly in four success handlers, (5) it makes "Clear exclusion" unreachable when zero labs exist, (6) it says the
remove-lab copy "is good" although that copy tells the student to use "the sidebar", which no longer exists, and (7) it
promises "copy updated" for this module without a single string. Every gap below has a concrete fix.

Change-type legend: unchanged · moved · renamed · moved+renamed · reorganized · behaviour-changed · UNMAPPED.

## 2. Dialog check (mechanics that must survive)

- All five injected dialogs: `.form-error[role=alert]` inside the `<form>` (withForm/opTask write there), `button[type=submit]` for busy-disable, `[data-dismiss]` closing via `closest('dialog')` bound once at load (line 59). Any dialog the redesign adds to `index.html` with `data-dismiss` is covered; dialogs created later must use `data-op-close`.
- `#auto-import-dialog` `close` event clears `importPreview` — do not swap the dialog for a non-closing panel.
- `#vm-dialog`: `#vm-reset-key` forced checked on open (rebuilt VMs); `#vm-password.required` flips on `host.auth`; after save the password is cleared and `required=false`; the helper-outdated branch keeps the dialog open with the form error.
- `#remove-lab-dialog`: hidden `#remove-lab-confirm-name` auto-filled (no typing); backend 409s ("The lab name changed…", "Wait for this lab backup or login job…") surface in `.form-error`.
- `manager-settings-dialog`: `#manager-reset` enabled only when the input is exactly `RESET`; on success every `dialog[open]` is closed and `opCaps=null`.
- `exclusion-menu` and `backup-all-review` use `opDialog` (eyebrow "NODE MANAGER", `data-op-close`) — the eyebrow should become "MANAGER" / "LAB" but that is operations.js' `opDialog`.
