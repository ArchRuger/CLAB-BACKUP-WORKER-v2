# cEOS: the review transaction of the real code on the live node (2026-09-27 01:00 UTC)

Run from a scratch `create_app` instance (its own data directory, never the deployed manager's) against
`clab-restore-square-ceos` (cEOS 4.35.0F, containerlab startup configuration): the design of OSPF + BGP,
dual stack, generated by the pinned engine, then `DesignApply._review_one` for `ceos`, which opened the
real transaction (`clabdsg-…` session), read the device, and aborted it (`show configuration sessions detail`
empty afterwards).

- The review took 4.7 s over one SSH connection: `render_desired` (clean base + candidate), `snapshot`, the
  staged session with the candidate, `show session-config`, `show session-config diffs`, `abort`.
- Result: reachable, ready, `added` 104, `removed` 0, `stale` 0, `conflicts` 0, `expected` 1
  (`no ip routing`: the device default the design switches on), no removals (first apply), created
  ancestors `interface Loopback0`, `router ospf 1`, `ipv6 router ospf 1`, `router bgp 65000` with its two
  address families, the two `route-map next-hop-self-… permit 10` objects.
- Protected settings left out, by name: the `normalize` file, `hostname ceos`, `logging monitor debugging`,
  `aaa authorization exec default local`, the eight `ip host`/`ipv6 host` lines, `interface Management0`
  (the image refuses `no lldp transmit`/`receive` there: the first run failed at lines 8 and 9 of the
  candidate until the filter left the block out), the three `mac-address` lines.
- The device normalises what it receives before it renders the would-be configuration: `ipv6 nd ra interval
  5` became `ipv6 nd ra interval msec 5000`; ownership taken from the device's rendering therefore owns the
  device's spelling, not netlab's.
